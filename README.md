# 人体感知雷达仿真代码说明

三个脚本分别对应运动状态区分、跌倒检测、微多普勒。它们共用一套 77GHz FMCW 参数和三个公共函数，所以可以单独跑，也可以串成一条处理链。

```
cd radar_human
% MATLAB 命令行里依次执行
proj4_motion
proj5_fall
proj6_microdoppler
```

需要在 MATLAB 里把当前目录加到路径（`addpath(pwd)`）。跑完会在命令行打印特征表，并弹出若干图窗。

## 一、参数怎么来的

发射线性调频信号 $s_T(t)=\exp\{j2\pi(f_0t+\tfrac12St^2)\}$，斜率 $S=B/T_c$。回波延迟 $\tau=2R/c$，去斜之后的中频信号为

$$s_{IF}(t)=\exp\left\{j2\pi\left[f_0\tau+S\tau t-\tfrac12S\tau^2\right]\right\}$$

其中 $f_0\tau=2R/\lambda$ 给出距离相位 $4\pi R/\lambda$，$S\tau t=(2SR/c)t$ 给出拍频 $f_b=2SR/c$。最后那一项 $\pi S\tau^2$ 是距离-多普勒耦合的残余相位，在 4m 内只有 0.013rad，代码里丢掉了；如果哪天把距离窗拉到 10m，它涨到 0.2rad，就得补。

距离 FFT 之后峰值 bin 的复值记为 $z$。相邻两个 chirp 之间：

$$\Delta\phi=\angle(z_{m+1}z_m^*)=-\frac{4\pi\Delta R}{\lambda},\qquad v=\frac{\Delta R}{T_{chirp}}=-\frac{\Delta\phi\lambda}{4\pi T_{chirp}}$$

这个式子是三个项目共用的测速基础。同样的差分放在帧与帧之间，不模糊速度从 $\lambda/(4T_{chirp})=6.49$ m/s 掉到 $\lambda/(4T_{frame})=0.10$ m/s，但位移灵敏度不变：$\lambda/(4\pi)=0.31$ mm/rad。呼吸 3.5mm 对应约 11rad 的相位峰峰值，所以 unwrap 相位能看清呼吸；翻身瞬间 3.5m/s 对应帧间 140rad，unwrap 必然崩掉。

| 参数 | 取值 | 推导/依据 |
|---|---|---|
| 载频 $f_0$ | 77 GHz | $\lambda=3.90$ mm |
| 带宽 $B$ | 1.5 GHz | 理论距离分辨率 $c/2B=10$ cm |
| chirp 时长 $T_c$ | 100 μs | $S=1.5\times10^{13}$ Hz/s |
| chirp 间隔 $T_{chirp}$ | 150 μs | 留 50 μs 给 PLL 切换 |
| ADC $f_s$ / $N_s$ | 1 MHz / 128 | $R_{max}=10$ m，距离 bin $=c f_s/(2SN_s)=7.8$ cm |
| 每帧 chirp 数 | 64 | $T_{frame}=9.6$ ms，帧率约 104 Hz |
| 不模糊速度 | 6.49 m/s（chirp 间）/ 0.10 m/s（帧间） | $\lambda/(4T)$ |

距离 bin 取 7.8cm 而不是理论分辨率 10cm，是故意过采样一档，这样目标落在两个分辨率单元之间时峰值 bin 不会来回跳。

公共函数只有三个：`radar_cfg.m` 出参数，`fmcw_echo.m` 按点散射轨迹生成中频矩阵，`peak_track.m` 做距离 FFT 并在指定距离窗里找峰值。回波是快时间 × 慢时间矩阵，噪声是复高斯白噪声，墙面杂波统一放在 4.4m、幅度 0.22，用来提醒后级"零速处总有个东西"。

## 二、项目4：运动状态区分与算法切换

这个项目的实际用途不是"识别人在干嘛"，而是给后级选处理链。静息微动走 unwrap 相位（做呼吸/心跳谱），大幅度动走 chirp 间差分相位和多普勒跟踪。商用人体雷达基本都是这个二选一的结构。

仿真三种轨迹：静坐（呼吸 3.5mm/0.27Hz + 心跳 0.6mm/1.05Hz）、翻身抬手（0.42m 位移在 0.18s 内完成，峰值速度 3.5m/s）、行走（0.6m/s 朝雷达走，叠加腿部摆动）。

提取三个特征：

- 帧间相位差 RMS：反映慢时间相位的抖动强度。静息只有呼吸那点变化，运动则因为相位绕回出现大数值。
- 距离 bin 净漂移及其占总变化范围的比例：行走是单向的，翻身是往返的，单看速度分不开，看距离趋势就能分开。
- R-D 谱在目标附近的多普勒展宽：静息几乎是一条线，翻身和行走会散开。

实测结果：

| 场景 | 相位差 RMS | bin 漂移 | 单向度 | 展宽 (m/s) | 判定 |
|---|---|---|---|---|---|
| 静坐呼吸 | 0.154 | 0 | 0.00 | 0.106 | 静坐微动 → unwrap 相位 |
| 翻身抬手 | 0.685 | 0 | 0.00 | 1.616 | 翻身/抬手 → chirp 间差分 |
| 行走 | 1.157 | -15 | 0.88 | 0.567 | 行走 → 多普勒跟踪 |

相位差 RMS 的门限取 0.4：静息实测 0.154，运动最低 0.685，中间留了近一倍裕量。单向度 = |净漂移| / (bin 变化范围)，行走 0.88、翻身 0，门限 0.7。这两个量都不依赖绝对幅度，换个人、换个安装距离不至于马上失效。

有个细节值得留意：翻身的 chirp 间相位增量约 2.1rad，还没到 $\pi$，差分相位还能解；但帧间增量上百 rad，unwrap 已经彻底失效。这就是"大幅度动切差分"的准确含义——不是差分比 unwrap 更准，而是 unwrap 在这个速度下根本没有唯一解。

## 三、项目5：跌倒检测

走速度路线，距离轨迹只做误报抑制。判据是四道与门：

$$|v|_{peak}>1.8\ \text{m/s},\quad \Delta R_{net}>0.6\ \text{m},\quad v_{tail,rms}<0.25\ \text{m/s},\quad R_{end}-\min R<0.2\ \text{m}$$

速度从 chirp 间差分相位算，不能用帧间——跌倒峰值速度 4.6m/s 对应的帧间相位是 140rad，早绕没影了。chirp 间不模糊速度 6.49m/s，够覆盖跌倒瞬间。

四道门限各管一种误报：坐下速度只有 0.65m/s，第一道就挡了；躺下速度 1.11m/s，同样挡掉；弯腰速度能到 1.48m/s，接近但没过线；快速弯腰速度 2.24m/s 过了第一道，但净位移只有 0.47m，第二道挡掉。如果有人弯得更急，最后两道"结束时要静止、姿态不能恢复"还会再拦一层。

实测：

| 场景 | 速度峰值 | 净位移 | 尾段速度 RMS | 姿态恢复 | 判决 |
|---|---|---|---|---|---|
| 坐下 | 0.65 | 0.31 | 0.000 | 0.00 | 不报（速度不足） |
| 跌倒 | 4.61 | 1.41 | 0.000 | 0.00 | 报跌倒 |
| 躺下 | 1.11 | 1.17 | 0.000 | 0.00 | 不报（速度不足） |
| 弯腰 | 1.48 | 0.47 | 0.000 | 0.47 | 不报（速度不足） |
| 快速弯腰 | 2.24 | 0.47 | 0.000 | 0.47 | 不报（位移不足） |

误报之所以是跌倒检测的难点，是因为"坐下"和"跌倒"在径向速度上只差一个量级，而"快速弯腰"和"跌倒"在速度上几乎重叠。单靠一个阈值无论怎么调都会顾此失彼，必须叠加速度持续时间、位移总量和事后状态。真实产品还会加高度轨迹（顶装雷达尤其依赖这个）和目标消失/重现的事件，这里没有展开。

这条路线也有它自己的漏报：主动缓慢躺下会被当成正常动作，而晕厥式滑倒如果初速度不高同样抓不到。速度和姿态本身就不是一回事，靠单一雷达的单条距离轨迹很难闭合，这是方法本身的边界，不是阈值调得不够细。

## 四、项目6：微多普勒

四肢摆动叠加在躯干上，距离-多普勒图上就不再是单条谱线，而是一片展宽的谱。人体步态约 1Hz，腿摆幅 0.28m 对应峰值微多普勒 1.76m/s；宠物小跑 3Hz、摆幅 0.09m，峰值速度反而和人体接近；三叶风扇 4Hz 旋转，每片叶片扫掠速度 4m/s，谱上是对称的两簇能量。

STFT 参数：慢时间采样率就是 chirp 重复频率 6.67kHz，窗长 0.3s（2000 chirp）、跳步 0.04s、FFT 4096 点补零到显示用。目标区间取 2.4–3.7m 内所有距离 bin，每个 bin 单独做 STFT 后在功率域累加。这里不能先把各 bin 的复值相加——不同 bin 的 FFT 相位参考不共用，相干相加会互相抵消。

时频图和 R-D 图在显示前都按各自峰值折成相对 dB。原先直接画 FFT 功率绝对值，幅度在 70dB 以上，配固定的 `caxis([-70 -25])` 会整片顶到饱和色，什么结构都看不见；而且 FFT 点数一变绝对幅度就跟着变，不同目标之间也没法比较。改成相对峰值后，人和宠物的谱图只剩 `±2m/s` 附近有能量，风扇则铺到 `±4m/s`，一眼就能分开。

实测：

| 目标 | 微多普勒展宽 | 峰值速度 | 包络调制频率 |
|---|---|---|---|
| 行走人体 | 1.124 m/s | 1.230 m/s | 2.00 Hz |
| 小跑宠物 | 1.203 m/s | 1.636 m/s | 6.00 Hz |
| 三叶风扇 | 2.843 m/s | 3.928 m/s | 12.00 Hz |

包络调制频率是这里最好用的分类特征。人 2Hz = 2×1Hz 步频（双腿交替，一个步态周期里能量起伏两次），宠物 6Hz = 2×3Hz，风扇 12Hz = 3×4Hz 的叶片通过频率。展宽这一项人和宠物几乎一样（1.12 对 1.20），单看它分不开，得靠调制频率。风扇的展宽和峰值速度都明显高出一截，反而最容易识别。

## 五、这套代码没做什么

点散射模型。没有 RCS 起伏、肢体遮挡、多径，也没有真实 ADC 的相位噪声、IQ 不平衡和杂波起伏。噪声只有复高斯白噪声，幅度是按经验填的，不是从板子标定出来的。

没有 CFAR 和检测环节，峰值搜索直接被限定在写死的距离窗里。真实链路要先做检测再跟踪，这里跳过了。

所有阈值都是在这组仿真轨迹上标出来的。换个安装高度、距离、体型，或者人穿了件吸波材料的衣服，都得重新取样标定。代码的价值在于把处理链和特征跑通，不是给出能直接上板的门限。

项目4的区分只做了三态，没有"跌倒""静止躺卧"等更细的状态；项目5没有接项目4的输出（真实系统里应该由项目4的"大幅度动"状态去唤醒跌倒检测器）；项目6的人体是几个等效散射点，不是完整人体网格。这些是有意留的边界，不是遗漏。
